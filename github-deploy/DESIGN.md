# Design rationale

Theme 4, Evaluation and Data Quality. Prototype: https://anthropic-stem-fellows-kaylal--est-demo-web.modal.run. Code: this repository.

## 1. Why this theme and this approach

The evaluations that set chemical, biological and cyber capability thresholds in model system cards are human-uplift trials, and the same design is used in productivity and education studies. One group works with the model, another without, and the difference in graded output is the uplift. These trials grade the outcome carefully and do not record how well each participant got information out of the model. In the one trial with public per-person data (OpenAI 2024), 4 of 50 participants given the model never messaged it and 20 percent of task responses were written with zero messages. Among the published trials read for this work (OpenAI 2024, RAND 2024, the Claude 3.7, 4 and 4.5 system cards, Zhang et al. 2026, the UK AISI and RAND 2026 cyber trial, Hong et al. 2026), two print any per-participant measure of how the model was used and none measures elicitation skill before randomisation. That unrecorded variance is the data-quality problem this tool addresses: elicitation skill enters the outcome in the treatment arm only, varies from person to person, and is averaged away in the per-arm (intention-to-treat) mean that system cards report, so two labs can run the same model on the same tasks and report different uplift because their participants asked differently, and neither report contains the number needed to tell.

The tool has two parts. The transcript scorer is an LLM-as-judge pipeline that reads the chat logs a trial already has and scores five elicitation behaviours per session, built to the standards an eval pipeline is held to: a judge that labels turns rather than grades, arithmetic fixed in code, a pre-registered judge-agreement check, control sessions with known scores re-scored alongside every input to anchor the scale, pinned checklists, and a content-hash cache whose key is returned with every result. The pre-test is a short level on non-hazardous material that measures the same behaviours before randomisation, so the score can be recorded as a baseline covariate or used to stratify. The scorer is the part that applies to trials already run; the pre-test is the part a future trial can adopt cheaply.

What to measure was not given by the literature. The trials and reporting guidelines reviewed (RAND 2024, OpenAI 2024, Hong et al. 2026, Zhang et al. 2026, Paskov 2026, the STREAM reporting standard) name variable prompting skill as a problem, and none measures it with a performance test. The same sources describe what weak use looks like, in debrief notes and author commentary rather than as defined constructs: one broad question instead of the specific ones, accepting a deflection, not checking what the model said, and not using what it gave. EST turns each description into a countable behaviour: coverage and specificity (what was asked for and how precisely), persistence (asking again after a non-answer, meaning a reply that declines, deflects or says nothing was found), verification (checking the model) and uptake (using what was obtained). That translation is this project's own; the sources motivate the five behaviours but do not define or validate them.

## 2. What is interesting or non-obvious

The obvious fix does not work, and the post-trial pipeline shows it against a known truth. A trial that has transcripts could score elicitation after the fact and report uplift among the participants who used the model well. `analyze_trial.py` does exactly that on the simulated 48-participant trial in `demo_trial_v2/`, where the true uplift is known by construction:

| Estimator | Estimate | Valid |
|---|---|---|
| E0, unadjusted difference in means | 0.613 | yes |
| E1, stratified on pre-test tertiles | 0.606 | yes |
| E3a, top third of in-trial elicitors against all controls | 0.776 | no |
| E3b, bottom third of in-trial elicitors dropped | 0.703 | no |
| Simulated true uplift | 0.613 | |

E3a and E3b condition the treatment arm on a variable measured after treatment and correlated with baseline ability, while the control arm stays unselected, so they change the quantity being estimated and add baseline differences to it. It is the same error as filtering evaluation samples on the model's own behaviour. A trial that wants uplift among capable elicitors needs the capability measured before randomisation, which is what the pre-test is for; the transcript scorer is for validation and description, not adjustment. (The pre-test and in-trial sessions in the simulation come from the same trait-driven personas, so E1's agreement with the truth is recovery of built-in structure, not evidence about people; the E3 bias is the point of the table.)

The assistant in each level is the measurement instrument. Seven lab-specific records sit behind a cooperative assistant with graded release rules: two volunteered, two released when the topic is raised, two only on a request for the specific record, and one withheld on the first ask and released on the second. Each score is a share between 0 and 1 (things done over things that could have been done) or 1/0 for did or did not (persistence and verification in a level, verification in a transcript). Because the tool wrote the scenario and logs the moment each record is released (the release log), four of the five behaviours are counted straight from that log with no judge at all. Only uptake, the share of obtained records that appear in the written answer, needs an LLM judge (the answer judge), and it reached an F1 (harmonic mean of precision and recall) of 0.96 against an independent blind labeller on 126 labels.

A transcript from a real trial has no release log, so the same five behaviours are observed differently. One judge call per session labels each participant turn against a short task checklist (which items it asks about, whether the ask is for a concrete record, whether it re-asks after a non-answer, whether it checks something the assistant said) and lists which items the assistant provided and which of those appear in the written answer. The same formulas then turn the labels into scores; the judge never assigns a grade, so every score traces back to specific turns and the two halves of the tool stay on one scale. A behaviour that could not be observed is reported as NA rather than 0 (persistence when the assistant never gave a non-answer, uptake when the session has no separate written answer), and the overall score is the mean of the behaviours observed with the count shown beside it. Scripted WEAK, MEDIUM and STRONG participants run through both halves and land in the same order. They ship as 12 control sessions with expected scores (logged by the level itself for the scripted three, the judge's build-time score for one low and one high participant from RealHumanEval, a public dataset of people coding with an LLM), re-scored alongside any upload so its scores are read against fixed points.

Evidence considered on how hard the measurement is, all from public data or other instruments rather than from EST on people (details in `docs/RESEARCH_NOTES.md`): single-conversation judge labels on two public human chat datasets (PRISM and RealHumanEval) have a person-level intraclass correlation (ICC, the share of score variance that lies between people) of 0.06 to 0.24; the closest published instrument, Weidmann, Xu and Deming's puzzle tasks with known answers, reaches ICC 0.44 per item and 0.82 over six items; one EST level therefore will not rank people reliably, three levels project to 0.43 to 0.70, which is why a trial would have participants take all three and why the transcript scorer asks for three or more sessions per person and reports a rank interval rather than a point rank.

## 3. Key design decisions and tradeoffs

Benign lab-troubleshooting scenarios instead of anything near the hazard domain. The test can be public, taken by anyone and shipped with its records inspectable in the browser in bring-your-own-key mode. The cost is that transfer from a cell-culture scenario to a hazardous task is unproven, and it is the main open assumption.

A fixed budget of 12 messages instead of a wall clock. Scores depend on what the transcript shows the participant extracted and used, not on typing speed, and an 18-minute cap on the participant's own clock (paused while the model replies) keeps a level to about 20 minutes. The cost is that message efficiency is not itself scored.

A cooperative assistant. Persistence is measured as re-asking after a non-answer from an assistant that will release the record on the second ask. This matches helpful-only trial designs (safeguards removed) and not safeguarded ones, where persistence means working around a refusal.

A judge that labels rather than grades. Having the LLM classify individual turns against a task checklist, with the arithmetic fixed in code, trades some flexibility for per-turn auditability and for one scale across the level and the transcript halves. The judge output, the task checklist used and the cache key are returned with every result. The checklist sets the scale: re-judging a session under the same checklist moved its overall score by at most 0.06, while two independently written checklists for the same task moved it by 0.35, so only runs scored against the same checklist are comparable.

Two pass/fail checks (G1, G2) on scripted participants before any human data, with the failures kept. G1 (STRONG > MEDIUM > WEAK on every level) and G2 (answer judge F1 at least 0.90) were frozen in `SPEC.md` before the first run. G1 failed twice with LLM-scripted participants (run 1 on uptake pooled across levels, MEDIUM 0.739 below WEAK 0.750; run 2 on pooled specificity and STRONG persistence) and passed on run 3 after the scripted participants were replaced by deterministic state machines with the checks, scorer and controller unchanged. All three runs and two edits to the scripted participants before run 1 are recorded in `results/g1_run3/REPORT.md`, and dated changes to the frozen design are in `SPEC_AMENDMENTS.md`. The checks show the mechanics discriminate scripted behaviour and nothing about humans.

A self-contained demo. Six sample sessions, their task checklist and the 12 control sessions ship with cached judge outputs, so the demo click completes in seconds with no new model calls; uploaded transcripts are judged live.

One Modal container, hosted credential on the server, and a data-handling rule. The hidden records and the API credential never reach the browser in hosted mode. The transcript scorer sends text to the model API, so the page tells users not to upload transcripts from sensitive trials (chemical, biological, cyber) and to run the command-line scorer where those transcripts live.

## 4. Extensions with more time

Predictive validity across the benign-to-hazard gap, which is the assumption everything else rests on. Score participants on the benign pre-test before a trial, then check whether it predicts the behaviours the transcript scorer finds in the trial's own hazard-domain logs and whether it explains outcome variance in the model arm. Only this establishes the pre-test as a covariate, and it needs no new hazardous material: the trial's existing transcripts are the criterion.

A safeguarded-assistant variant of persistence, so the instrument matches trials run against a model with refusals in place. The records stay benign; the assistant refuses until the participant reframes, so the score measures refusal navigation without hazardous content. In the meantime, red-team exercises can be scored with the transcript scorer against the exercise's own checklist or grading rubric, which gives a per-person elicitation measure alongside the jailbreak outcome, with the caveat that it confounds the person's skill with the model's safeguards.

A pilot with ten to twenty people taking all three levels, recording wall time, message counts, completion and per-level ICC. Every reliability figure above is a projection from scripted runs or from other instruments.

More and shorter items. The Weidmann data suggest six five-turn micro-levels would reach the reliability a covariate needs in the same hour; the design question is whether the persistence item survives the cut.

Adoption of `trial/SCHEMA.md`: the fields a trial needs to record (per-participant use, model snapshot, assistant condition, ceiling protocol, estimand) so that `analyze_trial.py` can report an elicitation ratio (participant score over the model-alone ceiling on the same task) that is comparable across trials.
